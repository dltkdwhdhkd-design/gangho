# 강호행을 일검풍운결처럼: 작업 지시문

아래 "지시문" 칸을 통째로 복사해서 새 대화의 첫 메시지로 주면 된다. 저장소(`dltkdwhdhkd-design/gangho`)가 연결된 세션이어야 한다.

## 지시문

```
강호행(저장소 dltkdwhdhkd-design/gangho)을 일검풍운결(逸劍風雲決, Wandering Sword)과 최대한 같은 느낌의 게임으로 뜯어고쳐 줘. 한 번에 다 하는 일이 아니라 아래 단계대로, 단계마다 올려 가며 하는 일이야.

# 일하는 방식
- 답은 한국어로, 꾸미지 않은 평범한 말로 해.
- 결과물은 파일로 보내지 말고 GitHub에 올린 뒤 주소만 줘. 확인은 https://dltkdwhdhkd-design.github.io/gangho/ 에서 해.
- 틀린 건 틀렸다고 먼저 말하고, 확인 안 한 걸 됐다고 하지 마. 화면은 직접 찍어 보고 말해.
- 단계 하나가 끝날 때마다 tools/의 시험(reach, door, edge, street, occlude, shop, life, heroine, playthrough)을 돌리고 올려.
- 게임 안에 유료 AI를 넣지 마. 혼자 하는 게임이야.
- 그림은 내가 ChatGPT로 받아서 zip으로 줄게. 요청서는 docs/chatgpt-characters.md(인물 HC번호)와 docs/chatgpt-backgrounds.md(배경 FB번호)에 있어. 그림이 아직 없는 단계는 지금 그림으로 틀을 먼저 만들고, 그림이 오면 갈아 끼워.
- 먼저 docs/hd2d-plan.md, docs/iso-layout.md, docs/chatgpt-characters.md, docs/chatgpt-backgrounds.md를 읽어.

# 목표 화면
일검풍운결은 HD-2D야. 세밀한 도트 인물이 입체로 만든 배경 위를 걷고, 카메라는 정면에서 살짝 내려다봐. 따라갈 것은 이 일곱 가지야.
1. 시점: 건물 앞면이 화면과 나란하고 지붕 윗면이 조금 보인다. 쿼터뷰가 아니다.
2. 깊이: 화면 위쪽(먼 곳)과 맨 아래(가까운 곳)가 흐리고 가운데만 또렷하다.
3. 빛: 해가 한쪽에서 들어 건물·나무·사람이 긴 그림자를 드리운다. 등롱과 창은 주변을 따뜻하게 밝히고, 밝은 곳은 번진다. 아침·낮·저녁·밤의 색이 뚜렷이 다르다.
4. 배경 질감: 도트가 아니라 고해상도 그림. 건물 키는 사람 키의 서너 배.
5. 인물: 3.5등신의 세밀한 도트. 지금(2.5등신, 키 15점)보다 훨씬 크고 자세하다.
6. 공기: 햇살 줄기, 먼지와 꽃잎, 연기, 물 반짝임, 먼 산 안개.
7. 층: 먼 산과 하늘 → 걷는 땅 → 화면 앞을 살짝 가리는 가지와 처마. 카메라가 움직이면 층이 따로 논다.

# 지금 게임
- 순수 JS 모듈, 캔버스 2D. 화면 320×180을 4배로 키운다. 한 칸 16점.
- 지도는 js/maps.js의 MapDef(길, 물, 소품, 충돌, 문, 출구)로 짜고, 문파와 고을은 js/base.js, 강호 전도는 js/world.js가 만든다. 땅은 G.world.paintArea가 칠한다.
- 소품은 js/tiles.js의 STAMPS(이름, 크기, 충돌 상자). 고해상도 그림은 assets/hd/<종류>/<이름>.webp에 두고 assets/hd/list.json에 적으면 같은 이름의 도트 대신 쓰인다.
- 장면은 js/field.js의 drawScene이 그린다. 사람은 js/core.js의 drawActorSprite(16점 칸 시트, 네 방향).
- 모드가 둘이다. 정면 모드(기본)와 쿼터뷰 모드(localStorage gangho_iso=1, js/isoout.js가 같은 평면도를 눕혀 그린다). 일검풍운결은 정면 모드 쪽이다.
- 사람이 그림에 가려지는 것은 js/occl.js가 막는다(가려지는 자리면 비켜 세우고, 주인공이 뒤로 가면 그 그림을 옅게).
- 전투는 js/battle.js, 이야기는 js/ctx.js와 story 쪽, 자유 모드는 saga/jianghu/free.

# 큰 결정 (먼저 나한테 확인받을 것)
작업을 시작하기 전에 아래 셋을 네 생각과 함께 짧게 물어봐. 내 답을 듣고 시작해.
1. 쿼터뷰 모드를 남길지. 내 생각은 "정면 모드를 일검풍운결처럼 만드는 데 집중하고, 쿼터뷰는 지금 상태로 두되 더 손대지 않는다"야.
2. 화면 해상도. 인물 키가 15점에서 40점쯤으로 커지면 320×180으로는 화면이 좁아. 안쪽 해상도를 640×360으로 올리고 2배로 키울지, 인물만 크게 그릴지. 보이는 범위(지금 가로 20칸)가 어떻게 달라지는지 그림으로 보여 주고 정하자.
3. 방 안을 무대 모양(뒷벽이 서고 앞벽이 없는)으로 바꿀지. 바꾸면 방마다 배경 그림 한 장을 깔고 그 위에 충돌과 사람 자리만 얹는 식이 된다.

# 단계
0. 시험 인물로 틀 잡기: 요청서의 HC0(주인공 걷기 한 장)을 내가 주면, 그 그림으로 새 인물 시트 규격(칸 크기, 키, 발 위치, 방향 셋 + 뒤집기)과 화면 해상도를 정한다. 넣는 도구(tools/)에 새 규격을 자르는 명령을 만든다. 여기서 정한 규격을 docs/에 적는다. 이게 끝나야 내가 나머지 인물을 받는다.
1. 빛과 깊이(그림 필요 없음): 화면 위아래 흐림, 시각별 색, 밝은 곳 번짐. 설정에 화면 효과 단계(끔, 보통, 높음).
2. 그림자와 등불(그림 필요 없음): 건물·나무·사람의 누운 그림자가 시각에 따라 돌고 길이가 바뀐다. 밤과 저녁, 방 안에서 등롱·창·화로 주변이 밝다.
3. 땅(그림 필요 없음): 땅을 두 배 곱게 칠하고, 물결이 움직이고, 물가의 집과 나무가 물에 비친다.
4. 인물 갈아 끼우기: 새 규격 시트가 있는 인물은 새 그림으로, 없는 인물은 지금 그림을 같은 키로 키워서 섞여 보이지 않게. 걷는 속도, 말 걸 거리, 충돌 상자, 말풍선과 이름표 높이를 새 키에 맞춘다. 전투 화면(js/battle.js)도 같은 시트를 쓴다.
5. 건물과 소품 갈아 끼우기(FB1~FB11): STAMPS에 "그림 높이" 칸을 더해 바닥 폭은 그대로 두고 위로 키 큰 그림을 그린다. 충돌과 문 자리는 안 바뀐다. 담은 토막을 이어 붙인다. 사람이 건물에 가려지지 않게 occl.js를 정면 모드에도 건다.
6. 층과 공기(FB12, FB13): 먼 배경이 느리게, 앞 장식이 빠르게 움직인다. 숲과 산중에 햇살 줄기, 지도마다 먼지·꽃잎·눈.
7. 방 안(FB14~): 큰 결정 3에서 정한 대로.
8. 강호 전도: 조각으로 칠하는 지도라 2배 땅과 그림자를 조각 단위로 만든다. 맨 나중에.
9. 손맛: 걷기 시작과 멈춤의 부드러움, 카메라가 살짝 늦게 따라오기, 건물에 들어갈 때 화면 전환, 대화할 때 살짝 당겨 보기. 일검풍운결 영상을 보고 빠진 것을 찾아 목록으로 주고 내가 고른 것만 한다.

# 지켜야 할 것
- 지도 자료(길, 담, 문, 사람 자리, 충돌, 이야기 좌표)는 바꾸지 않는다. 그림과 그리는 층만 바꾼다. 꼭 바꿔야 하면 먼저 말해.
- 이야기 진행이 깨지면 안 된다. 단계마다 playthrough 시험을 끝까지 돌린다.
- 쿼터뷰 모드가 깨지면 안 된다(남기기로 한 동안은).
- 휴대폰에서도 돌아야 한다. 흐림과 번짐은 값이 드니 화면 효과 "끔"에서 지금만큼 빨라야 한다.
- 새 그림이 반쯤만 들어온 상태로도 어색하지 않아야 한다. 새 그림과 옛 그림이 한 화면에 섞일 때 크기와 밝기가 튀지 않게 한다.
- 단계마다 청하진, 남궁세가, 낙양, 객잔 방을 낮·저녁·밤으로 찍어 직접 보고, 일검풍운결과 나란히 놓았을 때 어디가 아직 다른지 솔직하게 적어 줘.

지금 할 일: 문서들을 읽고, 큰 결정 셋을 물어보고, 내 답을 받은 뒤 1단계부터 시작해. 0단계는 내가 HC0 그림을 주면 끼워 넣어.
```

## 그림 받는 순서

2. 그동안 배경 **FB1~FB4**(집, 가게, 고을 건물)를 받는다. 배경은 규격과 상관없이 쓸 수 있다.
3. 규격이 정해지면 인물 1순위(주연 12명)부터 받는다.
